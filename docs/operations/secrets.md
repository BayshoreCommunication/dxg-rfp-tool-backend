# Secrets & Environment Variables

> Rule zero: secrets exist **only** in AWS Secrets Manager (runtime) and the
> deployment platform's stores. Never in git, never in CDK templates as real
> values, never in chat/tickets. `.env` files are for local dev only and are
> gitignored.

## Where secrets live

| Secret | Contents |
|---|---|
| `rfpilot/<env>/app` | The application's entire secret env (17 keys, table below) |
| `rfpilot/<env>/redis-auth` | Redis AUTH token (composed into `REDIS_URL`) |
| RDS-generated master secret | `rfpilot_admin` password (composed into `POSTGRES_URL`) |

**How apps get them:** ECS task definitions map each key via `valueFrom`;
values are injected as env vars **at task start**. Rotating a value
therefore requires a restart:
`aws ecs update-service --cluster rfpilot-<env> --service <svc> --force-new-deployment`.

## Key reference (`rfpilot/<env>/app`)

| Variable | Purpose | Source |
|---|---|---|
| `JWT_SECRET` | Access-token signing. Rotation invalidates all sessions | generated by compose script |
| `OTP_PEPPER` | OTP hashing pepper | generated |
| `BFF_SHARED_SECRET` | Frontend BFF ↔ backend auth. **Must match the value configured in the dashboard/admin deployments** | generated |
| `ADMIN_SIGNUP_SECRET` | Gates `POST /api/auth/admin/signup` | generated |
| `AI_SAFETY_IDENTIFIER_SECRET`, `TELEMETRY_PSEUDONYM_KEY` | AI governance hashing | generated |
| `MONGODB_URL` | Atlas connection string (no db in path — db comes from `MONGODB_DB_NAME`) | operator |
| `POSTGRES_URL`, `POSTGRES_MIGRATION_URL` | RDS URLs | composed from RDS secret + endpoint |
| `REDIS_URL` | `rediss://:<token>@<endpoint>` — scheme **must** be `rediss`, token URL-encoded | composed |
| `OPENAI_API_KEY` | Live AI | operator |
| `GOOGLE_CLIENT_ID` | Google sign-in | operator |
| `SMTP_HOST`/`SMTP_PORT` | `email-smtp.us-east-2.amazonaws.com` / `587` | operator |
| `SMTP_MAIL` | From address (`noreply@dxg-agency.com`) | operator |
| `SMTP_USER`/`SMTP_PASSWORD` | **IAM-derived SES SMTP credentials** (user `rfpilot-<env>-ses-smtp`); username is an access-key id, *not* an email | operator |

Non-secret configuration (feature flags, AI release, DB name, CDN base,
ClamAV host, etc.) is **code**: `sharedEnvironment` +
`config.aiEnvironment` in
[`deploy/aws/lib/app-stack.ts`](../../deploy/aws/lib/app-stack.ts) /
[`config.ts`](../../deploy/aws/lib/config.ts). Domain/cert values flow from
**environment-scoped GitHub variables** (`CERTIFICATE_ARN`, `API_DOMAIN`,
optional `FRONTEND_URL`/`ADMIN_URL`) into CDK context at deploy time.
Local-dev variables are documented in [`.env.example`](../../.env.example).

## Filling / rotating

- **Bootstrap & derivables:** run
  [`deploy/aws/scripts/compose-app-secrets.sh <env>`](../../deploy/aws/scripts/compose-app-secrets.sh)
  — generates the six random signing secrets (when still `REPLACE_ME`) and
  composes the three database URLs from stack outputs, displaying nothing.
  It then lists which external keys remain for the operator to fill.
- **Reading/writing single values** without displaying them: pipe through
  `jq` merges, e.g. fetch → `jq '. + {KEY:$v}'` → `put-secret-value`.
  Validate afterwards with a **boolean** check:

  ```bash
  aws secretsmanager get-secret-value --secret-id rfpilot/<env>/app \
    --query SecretString --output text | \
    jq -r 'to_entries|map(select(.value=="REPLACE_ME" or .value==""))|if length==0 then "ALL KEYS FILLED" else "MISSING: \(map(.key)|join(","))" end'
  ```

- Staging and production values are **fully independent** — sharing a
  signing secret across environments would make staging tokens valid in
  production.

## ⚠️ The secret-wipe footgun

The Data stack defines the secret's initial value via `secretObjectValue`
(all `REPLACE_ME`). **Any change to that map, deployed against a live
environment, resets every key to placeholders.** This happened once
(2026-08-02) when CI implicitly deployed the Data stack — which is why CI
now deploys with `--exclusively`, and why Data-stack deploys are manual and
deliberate.

### Recovering a clobbered secret

Secrets Manager keeps previous versions. Restore without ever touching
plaintext:

```bash
aws secretsmanager list-secret-version-ids --secret-id rfpilot/<env>/app
aws secretsmanager update-secret-version-stage --secret-id rfpilot/<env>/app \
  --version-stage AWSCURRENT \
  --move-to-version-id <good-version-id> --remove-from-version-id <bad-version-id>
# then force new deployments so tasks pick it up
```

## Never commit

`.env*` (except `.env.example`), Atlas URLs, API keys, SMTP/IAM
credentials, JWT/BFF secrets, dumps of Secrets Manager values, or real
customer data in fixtures. CI's cross-repo secret guard and review are the
backstop — don't test them.
